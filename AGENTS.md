# HisFullGlory Daily Walk

Maintain the existing English mobile-first faith platform: React, strict TypeScript, Vite, plain semantic CSS tokens, Supabase and installable PWA. Primary navigation: Home, Bible, Pray, Community, More. Use lightweight URL routing, feature modules and provider interfaces; do not rebuild from scratch.

Use explicit idempotent forward migrations from hfg-daily-walk:v1; never erase recoverable legacy data. Journals, notes, private prayers, reading preferences and progress stay local unless a user explicitly publishes a selected entry. Never log sensitive text or identity. Use only legally usable WEB Scripture with provenance; unavailable licensed content must be honest.

Preserve magic-link auth, private profiles, three rooms, prayer wall, realtime and cooldowns. Require versioned terms before posting; use private reports, blocks/mutes, author snapshots, narrow grants and RLS. Anonymous public identity must not be recoverable by ordinary clients. Users cannot approve/moderate support requests or forge author/timestamp/provider/payment state. No public emails, private chat, media uploads, ads inside community, or browser admin role.

Keep Jesus at the Center. Use warm Light/Dark/System semantic tokens, Manrope, safe areas, 44px touch targets, visible focus and reduced motion. Cache app shell/static Bible only, never dynamic/private responses. Commerce stays on HisFullGlory. Giving uses verified official external checkout and manually reviewed allowlisted individual fundraisers. HisFullGlory never handles money, bank/card details, KYC, refunds or receipts. Native payment adapters remain disabled until server, webhook, recipient and legal gates exist.

Run npm ci, npm test, npm run security, npm run build and npm run test:browser. Apply numbered migrations through 004; an existing 003 installation needs only 004. Preserve regression tests; test migration, route parsing, lifecycle, capabilities, analytics, UGC and giving cross-user authorization. Inspect final diff/assets/lockfile for secrets and licensing. Work sequentially with no agent delegation; screenshots only to diagnose a defect. Commit once on the current branch after checks; do not rewrite history or push before checks pass.

Do not add licensed Bible datasets/APIs without a license, runtime AI, unconfigured auth/push/sync, fake payment success/totals, fund custody, payment secrets, random chat, paid services or live-store/DNS changes. Native compilation/device verification must never be claimed without tooling/evidence. No deployment is authorized.

Module map: src/platform/persistence.ts owns local migration; src/storage.ts preserves calendar/legacy state; src/platform owns routing/capabilities/theme; src/bible owns legal Scripture/provider/editorial distinctions; src/features owns local spiritual flows; src/giving owns catalog/provider contracts; src/community.tsx preserves legacy chat; src/social owns safe UGC client/components; supabase/migrations owns additive server authorization; docs describe actual operational boundaries.
