# Decisions

- Extend the existing React/Vite/Supabase project and preserve original schema, chat rooms, auth, plans, products and calendar logic. Feature modules replace the old four-tab shell; no framework/backend rewrite.
- Use native browser history and a SPA rewrite for stable shareable routes. No routing or state-management dependency was necessary.
- Preserve v1/v2 raw storage and migrate explicitly to v3; unknown/corrupt current state is write-blocked. Valid journals and all original plan progress remain recoverable. Private data stays local with isolated guest/account profiles and no automatic guest adoption. Export is plaintext and must be handled as private data.
- Import the complete official public-domain WEB bulk file, not scrape Bible sites or invent verses. Offline package is 5.27 MB before compression, deliberately separated from the ~361 KB JS application bundle. Verse omissions are marked, not filled with invented Scripture.
- Keep editorial context limited to checked textual observations in Psalms 23/121 and Romans 8. Other passages give an honest unavailable state. General study prompts are editorial, not historical/linguistic scholarship. Future NLT, NIV, ESV, NKJV, NASB and original-language providers require explicit licenses, attribution, usage/caching allowances, authoritative data and a distinct provider adapter before adding selectors.
- Supply 15 original five-day topical journeys. They intentionally reuse a small pool of verified WEB selections with original topic applications rather than manufacture new scholarship or therapeutic advice. They supplement the three preserved original plans.
- Public anonymous content exposes content IDs and display snapshots, never raw author UUIDs. Resolve report/block targets inside RPCs. Reports, block lists and audits are private; no public profile/people directory or direct messaging.
- Accept community rules explicitly and enforce the current version on the server, including original post flows. Use durable cooldowns and narrow RPCs; client checks alone are insufficient. Manual moderation is a real operational prerequisite, not an invented automated service.
- GiveWell checkout is one official exact URL with an explicit program-selection instruction for each evaluated cause. No guessed deep-link parameters or fake project totals. Personal support is an externally hosted GoFundMe directory with private drafts and manual review; no self-approval, bank/crypto/direct-payment fields, unverified progress or fund custody.
- Keep payment-domain contracts but disable Stripe/Mollie calls completely. No VITE flag can activate native collection. Webhooks, recipients/KYC, reconciliation, legal clearance and release flags are future server work, not a frontend mock payment flow.
- Persist Light/Dark/System with semantic tokens and live OS changes. Save six notification preferences without pretending delivery exists or prompting for unavailable permissions. Google/Apple auth are not offered as working controls.
- Deliver a PWA and document native adapter boundaries. Capacitor/Xcode/Android and App Store submission are deferred because there is no native project/toolchain verification in scope. No deployment or DNS/store change is performed.
- Add meaningful state/privacy/SQL/browser behavior checks. Browser QA is headless at 375/390/768/1280px in both themes and captures no screenshots. SQL checks exercise local PostgreSQL privileges; hosted auth/Realtime and native devices remain release gates. See docs/QA_REPORT.md for evidence and limits. Playwright is a development-only dependency; it is absent from the production bundle.

- Extend existing posts with topics, one-level replies and safe source attachments in 005; preserve immutable 001–004. Membership is explicit and private. Ranking uses distinct legitimate supporters, not spiritual worth; named reputation excludes anonymous, removed, hidden and parent-hidden contributions. Unique vote keys and transaction locks protect writes; genuine concurrent-session validation remains pending.
- Use deterministic explicit topic choices for local recommendations, never prayer/journal analysis, sensitive commerce targeting or invented popularity. Paths/challenge use a small actual Scripture/prayer/journal corpus and private user-marked progress. Circles v1 is implemented locally in 006 with scoped consent/moderation tests; accountability, helper notifications and Prayer Chain remain future slices.
- Retain checked editorial notes while preparing scope fallback and grounded server-provider contracts. No wider scholarly corpus, AI response or verified-expert badge is fabricated. Billing/contributor contracts remain disabled without backend, review and legal processes.
- Runtime themes passed baseline tests; only a demonstrated pre-React first-paint defect was fixed. Preserve explicit Light/Dark/System choices and use a nonsensitive appearance hint.


- Implement Circles v1 in additive migration 006 while preserving the exact pre-pass bytes of 001–005. Use existing posts/reactions/votes/reports/blocks/audit, not parallel social tables. New raw Circle tables deny all application access; narrow RPCs serialize safe metadata and scoped answers.
- Privacy, owner and slug are immutable. Authenticated discovery intentionally reveals limited private metadata; exact member counts and identities stay scoped. Erase answers on review/withdrawal/closure and retain unresolved answers only for their pending review, with explicit withdrawal.
- Exclude all Circle posts from legacy public readers and global reputation. Public Circle discussions remain public on dedicated routes; this conservative boundary avoids private activity signals and preserves existing feed contracts.
- Public join and private application are explicit; removed members cannot self-restore. Owners cannot leave or transfer; closure disables reads/mutations and clears pending answers. Group roles do not imply credentials, theological authority, expertise or platform moderation.
- Preserve primary navigation and semantic theme tokens. A native dialog confirms destructive actions; controlled SDK browser evidence is distinct from real hosted Auth/API and simultaneous-session QA. No remote migration, commit, push, deployment, new dependency or native compilation is part of this pass.
